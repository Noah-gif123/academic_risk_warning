- **#4**：`ReentrantLock` 在本机单 JVM 场景下看似能防并发刷新，但 `/api/stats` 是 HTTP 接口，**Spring MVC 默认是多线程处理请求**，而 `ReentrantLock` 是**线程级锁，不是请求级锁**。若两个请求同时 hit `refresh()`，且 `refresh()` 被多个 Controller 方法调用（如 `/api/stats/summary` 和 `/api/stats/ab` 都可能触发），则 `lock.tryLock()` 只能拦住同一线程重入，**完全无法阻止跨请求并发刷新**。更致命的是：该锁未绑定到 refresh 的幂等 key（如 `engine_version`），导致「v3.0-base-fixed」和「v3.0-post-factor」两次重算仍可能并发执行 → 物化表写乱、`calc_status` 覆盖、快照时间戳错位。**真要防，必须用数据库行锁或 version+select for update，而非本地锁。**
