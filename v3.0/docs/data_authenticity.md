# P1 数据真实性与归因边界（限制 1）

> 结论：P1 的统计看板数字**内部自洽、可复现**，但 P1-0 的生命周期/干预/对照组是**演示构造数据**，
> 不能当作真实业务的因果结论。本文给出构造方法、安慰剂检验与引用边界。

## 1. 哪些是真实数据，哪些是构造数据

| 数据 | 来源 | 性质 |
|---|---|---|
| 学生/选课/成绩/考勤/风险分/风险等级 | v3.0 生成器（seed=20261108）+ 风险引擎 v2.1.0 | 拟真数据，用于演示规模与分布 |
| `course_factor`（课程因子 0.90–1.15） | P0-2 按历史挂科率初始化 | 规则计算，可复算 |
| 告警生命周期（create/handle/close、状态） | P1-0 `GenLifecycle` | **构造**（固定 seed、固定分布） |
| 干预记录、T+7 复评等级、TREAT/CONTROL | P1-0 `GenLifecycle` | **构造**（TREAT 改善概率 58%、CONTROL 27%） |
| `stat_daily_class` 历史（62 天） | P1-0 回填，`source='DEMO_BACKFILL'` | **构造**；当天行由物化任务写 `MATERIALIZED` |
| 周 KPI / 干预成效 | P1-3 物化任务从上述数据计算 | 计算真实，但输入含构造数据 |

构造规则（详见 `v3.0/tool/demo/GenLifecycle.java`）：
- 662 条告警按 seed 分散到 2026-09-15 ~ 2026-11-05，状态分布约 ACTIVE 20% / HANDLING 25% / CLOSED 55%；
- 干预组（60%）改善概率 58%，对照组（40%，本周期仅复评）27%；T+7 复评落在第 7–14 天；
- 日快照按“越早风险越高、向当前收敛”回填，事件计数来自真实告警/干预时间线。

## 2. 安慰剂/置换检验（placebo test）

目的：验证“TREAT − CONTROL = 29.54pp”不是标签随机分配造成的。

- 方法：把 TREAT/CONTROL 标签随机打乱 5,000 次，重算改善率差值，得到零分布；
- 结果（`v3.0/eval/placebo.json`，seed=20261108）：

| 项 | 值 |
|---|---|
| TREAT | 162 / 299 = **54.18%** |
| CONTROL | 52 / 211 = **24.64%** |
| 观测差值 | **29.54pp** |
| 零分布 95% 区间 | [−8.46pp, 8.52pp] |
| 置换 p 值 | **≈0.0002**（5000 次中仅 1 次更极端） |

结论：差值远超标签随机波动，说明**演示数据内部的干预效果是刻意构造的、且可被该检验识别**；
但这不是真实因果识别——真实业务仍需随机对照/断点回归/倾向得分等设计。

复现：
```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File v3.0/tool/run_placebo.ps1
```

## 3. 引用边界（论文/答辩必须写）

1. 数据为**演示构造**，P1-0 生命周期与对照组是“准实验”设定，不是真实干预净效应；
2. 置换检验只说明“差值非标签随机”，**不能替代真实因果识别**；
3. 所有统计口径与物化流程可复现（见 `evidence/P1.md` 与 `ci.ps1`），但数字随 seed/数据重建而变；
4. 若用于真实业务，需接入真实告警/干预数据，并重新评估改善率与对照组差值。

## 4. 与 P1-0/P1-3 的关系

- P1-0 生成器是**唯一**构造入口；重跑 `run_v3_pipeline.ps1` 会用同一 seed 重建同样的生命周期；
- 物化任务不“编数字”，只从 `alert_record`/`intervention_record`/`stat_daily_class` 聚合；
- `stat_daily_class.source` 区分 `DEMO_BACKFILL` 与 `MATERIALIZED`，可审计哪些行是回填。
