# AI 群聊工作台（v3.0 头脑风暴用）

一个本机小工具，**两种模式**，共用同一个服务和同一批 key：

| 模式 | 地址 | 是什么 |
|---|---|---|
| **群聊模式**（推荐） | `http://127.0.0.1:8099/room` | 真正的房间：你打字、@谁谁回、AI 之间自己接话、能派活到任务板 |
| 会议模式 | `http://127.0.0.1:8099/` | 一键跑「10 视角 × 4 轮」结构化评审，出合并总表 |

- 不是产品功能，是**开发辅助工具**；不进 v3.0 系统，不碰 `backend/`、`frontend/`、`sql/`
- 零依赖、零构建：一个 `server.mjs` + 两个 HTML
- 没有 key 也能跑（Mock 模式），只是看流程

## 零、群聊模式怎么用（你可能就想看这段）

打开 `http://127.0.0.1:8099/room`，底下就是输入框。

**三种说话方式：**

| 你做什么 | 谁回复 |
|---|---|
| 直接说，不 @ 任何人 | **值班**的人（左栏带 ⭐ 的，默认 3 个） |
| `@某个成员` | **只有他回** |
| `@全体` | 群里所有人都回（贵，慎用） |

**AI 自己接话：** 每次回复完，刚才说过话的人会自动再来 **2 轮**互相补充；没有新东西就输出 `[PASS]`（页面显示"弃权"，不占版面）。两轮都没新内容 → 自动收口。

**派活：** 在输入框写任务 → 在 @ 里选中**恰好一个**人 → 点「派活」。任务进右侧任务板（待办→接手→完成），被派的人会回一份 3 条执行计划（动什么文件/怎么自验/要谁配合）。

**预算：** 每个房间硬上限 **60 次调用**，到了自动停。顶部提示会显示累计调用次数。

**存档与导出：** 房间状态每轮自动存到 `v3.0/tool/ai_room/rooms/<roomId>.json`（重启服务可续）；点「导出」写 `v3.0/eval/room_*.md`。

**参考成本（实测）：** @全体一次 = 10 次回复 + 2 轮接话 ≈ **18 次调用**；只跟值班聊一次 ≈ **7 次调用**。按国内模型价格，一次完整讨论几毛到两块钱。

## 三、它怎么开会

```
R1 独立发散    10 个视角并行作答，互相看不到（防止第一个发言定调）
   ↓
R2 匿名交叉    清单打乱匿名后发回，每个视角只许「挑 3 条站不住的 + 补 3 条独有的」
   ↓
R3 红队攻击    两个专职红队：一个模拟答辩现场、一个专攻交付风险，只挑刺不给优点
   ↓
R4 收敛裁决    一个裁决者去重合并成总表：编号/缺口/补法/人日/是否动已定决策/答辩价值/争议
```

设计上的三个刻意选择：

1. **R1 必须并行且互不可见** —— 否则互相锚定，只会产出「大家都同意」的废话
2. **R2 匿名** —— 不告诉它是谁提的，避免权威偏见和互相吹捧
3. **R4 保留「争议」列** —— 多个模型都同意不等于对；少数派意见必须留在表里交人判断

## 四、界面上有什么

| 区域 | 用途 |
|---|---|
| 顶部 | 模型 key 状态（绿点=已配置）、真实/Mock 切换、开始/停止/导出 |
| 左栏 | 10 个视角可勾选；点卡片展开它的 system prompt（可用来判断这个视角靠不靠谱） |
| 中间 | 群聊流：每个角色一个气泡，实时流式输出，显示耗时与字数；R4 自动渲染成表格 |
| 右栏 | 进度日志、Brief 编辑器（改了随本次运行提交）、导出路径 |

## 五、产物

跑完点「导出 Markdown」，写到：

```
v3.0/eval/brainstorm_YYYYMMDD_HHMM.md
```

里面包含 Brief、每轮每个角色的完整输出、最终总表。答辩时可以说「做过 10 视角评审」，这份文件就是证据。

## 六、改配置（不改代码）

`room.config.json` 里可以改：

- `brief`：给所有模型的背景说明。**这是产出质量的主要来源**，越具体越好（约束、已定决策、已知不足、交付格式）
- `roles[]`：增删视角、改 `system`、改绑哪家 `provider`/`model`
- `redTeam[]`：红队人设
- `judge`：裁决者用哪家模型（建议用推理最强的那家）
- `concurrency`：每家模型并发上限，默认 2（避免被限流）

## 七、成本

一轮完整会议 ≈ **21 次调用**（10 R1 + 10 R2 + 2 红队 + 1 裁决），每次 1–3k token。
按国内模型价格，**一次大约几毛到一元多**。想省钱：只勾 4–5 个视角（≥2 就能跑），或在 `phases` 里关掉某一轮。

## 八、各家模型的坑（实测记录 2026-11）

| 厂商 | 坑 | 配置里怎么解决 |
|---|---|---|
| **Kimi（kimi-k3 / k3.1-pro）** | ① 思考型模型，思考会吃光 `max_tokens` 导致正文为空（实测 7399 字思考 / 正文 0 / 耗时 207s）② 组织级并发上限 **1**，并行必 429 ③ 温度锁死：开思考只允许 1，关思考只允许 0.6 | `extraBody: {thinking:{type:"disabled"}}` + `concurrency: 1` + `temperature: 0.6` + `maxTokens: 2600` |
| **豆包 / 火山方舟** | `model` 不能填模型名，必须填**推理接入点 ID**（`ep-...`） | 方舟控制台复制 `ep-xxx` 改 `providers.doubao.model`；不改就别用豆包 |
| **通义百炼** | key 可能是 `sk-ws-...` 工作空间格式（实测有效） | 无需特殊处理 |
| 通用 | 部分模型只接受固定 temperature，但报错里会带数值 | 服务会**自动从报错读出允许值并重试一次**，无需手改 |

> 换模型/换 key 后先跑 `node check.mjs`：它做一次最小真实调用，验证「key 可用 + 模型名对 + 温度可接受」。

## 九、常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 页面全是 `Mock` 标记 | keys.json 没填或格式错；改完点刷新（服务会重读 key，但角色绑定要重启服务） |
| 某个角色报 `HTTP 401` | 那家的 key 无效或没额度 |
| `HTTP 404 model not found` | `model` 名字不对；跑 `check.mjs` 看，或去控制台抄准确模型名 |
| 某个角色正文为空、只有"思考" | 思考型模型把预算吃光了：给它配 `extraBody:{thinking:{type:"disabled"}}` |
| `HTTP 429` | 并发超了：调低该 provider 的 `concurrency`（Kimi 必须是 1） |
| 输出很笼统 | 80% 是 Brief 写得太虚；把「不可重议」和「已知不足」写细 |
| 想重看历史 | 服务内存保留 30 分钟，刷新页面会丢失；重要结果先导出 |

## 十、边界（说实话）

- 它**擅长**补清单型缺口：失败恢复、权限、可观测性、成本、并发、合规、评测自证
- 它**不擅长**判断「你这个答辩能不能过」「这些活你干不干得完」——那是你和我按真实进度定的
- 别指望它给出「完美 v3.0」：多模型共同的盲区依然存在，而且模型天生爱附和
