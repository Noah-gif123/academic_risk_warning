# v3.0 规划：Agent 化 · 拟真数据 · AI 亮点 · 统计分析

> 版本目标：**从「一份能讲清的报告」升级为「一个会自己查、会自己算、能证明成效的系统」。**
> 前提：v2.0 已定稿（判定可复算、报告可对账、三层降级、六类 AI 场景）。
> 本文件只做规划，不改代码；按你的要求只记录在本机，不推送远端。

## 零、先对齐现状（v2.0 收尾时的实测口径）

| 议题 | 现状（有证据） | v3.0 要补什么 |
|---|---|---|
| C 通道跨班可比 | **已实现且是主力**：540 条判定中 524 条 `active_channel='C'`，16 条走 `A`；`delta_used` 全部非 0、`course_factor_used` 全部 ≠ 1 | 不是补实现，而是**让它产生可解释的差异**：构造跨班难度差、教师松紧差异、历史挂科率真实分布；把 Δ / 因子 / 熔断原因做成可视化校准页 |

| 统计与图表 | 只有零散 overview / coverage 接口；前端无图表库 | 独立统计模块 + 物化快照 + ECharts 看板 + 预警成效闭环指标 |
| Agent | 只有「工作流 + 分层职责」，没有工具调用/多步推理 | 自研轻量 Agent 编排（工具注册 + 规划循环 + 护栏 + 留痕），可选接 Dify Agent |

## 一、轨道 A：Agent 化（让系统自己会查、会算、会解释）

### A1. 目标

把 v2.0 的「六个一次调用场景」升级为**能多步取数、能自查、能给出行动清单**的 Agent：

> 辅导员问「计算机1班这周为什么红灯变多了？」→ Agent 自己查：风险分布变化 → 集中风险课程 → 多门预警学生 → 最近干预记录 → 相关课程资料，最后给结论 + 3 条动作，并附每步取数证据。

### A2. 两条路线（建议 A 为主、B 为辅）

| 路线 | 做法 | 优点 | 代价 | 结论 |
|---|---|---|---|---|
| **A. 自研 Agent 编排**（推荐） | Java 内实现 `ToolRegistry` + 规划循环（ReAct 风格）+ 结果校验 + 留痕，工具即现有 Service/API | 完全可控：工具白名单、只读、超时、金额/次数限额、每步留痕，能复用 v2.0 的三道校验 | 需要写编排与提示词工程（约 1 个迭代） | **v3.0 主线** |
| B. 接 Dify Agent | 把我们 8–10 个只读接口封装成 OpenAPI 工具，交给 Dify 做规划 | 演示直观、可视化编排、少写代码 | 编排在外部（版本/成本/数据出域不好控），降级路径要重做 | 作为「可选第二条通道」，与现有多通道降级一致 |

### A3. 工具清单（第一版 8 个，全部只读）

| 工具 | 入参 | 返回 | 对应现有能力 |
|---|---|---|---|
| `getClassRiskStats` | teachingClassId / termId | 红橙黄绿、未关闭预警、平均分 | 教师端总览 |
| `getRiskTrend` | teachingClassId / 周数 | 按周的风险分与等级序列 | **需新增（统计模块）** |
| `getCourseCompare` | offeringId | 各班红黄灯、平均分、最低分 | 课程报告事实包 |
| `getStudentRisk` | studentId / enrollmentId | 判定依据三通道、缺勤、需考分 | 预警详情 |
| `getInterventions` | studentId / 班级 | 干预记录与成效 | 干预模块 |
| `retrieveCourseDocs` | courseId + 问题 | 课程资料片段（带文档名/段号） | RAG 检索 |
| `getAlertExplain` | alertId | 解释卡四段（复用） | AI 解释卡 |
| `draftIntervention` | studentId + 类型 | **只生成草稿，不落库**（需人工确认） | 新增（写操作走"草稿"） |

### A4. 编排与护栏（关键，决定能不能上场）

1. **单轮最多 4 步工具调用**，超时 20 秒，总 token 上限 3000；超限即中止并降级为「直接回答 + 提示信息不足」。
2. **工具只读**：任何写操作（登记干预、发通知）只能生成草稿，由人在界面上确认。
3. **每步留痕**：`ai_run_step` 记录 `tool_name / 入参摘要 / 返回摘要 / 耗时 / 校验结论`，前端可展开看「Agent 是怎么查的」。
4. **数字来源校验**：Agent 最终答案里的数字必须能在工具返回里找到（复用 v2.0 的数字白名单 + 定向对账）。
5. **失败可解释**：任一步工具失败 → 明确说"哪一步没查到"，不允许编造（沿用 v2.0 的"不硬凑"原则）。

### A5. 验收指标

- 20 个预设问题集（跨班、跨课程、单生、趋势、干预成效各 4 条）：工具选择正确率 ≥ 85%、最终答案数字一致率 100%、平均时延 < 8 秒、单次 token < 3000。
- 至少 3 条问题需要 ≥3 步工具调用才能答出（否则说明 Agent 没意义）。

## 二、轨道 B：数据层（把演示数据做成"像真的一样有差异"）

### B1. 拟真基础数据

| 项 | 现状 | v3.0 做法 |
|---|---|---|
| 学生 | 135 人，1 人叫「学生1」 | 姓名库（姓氏 × 名字，去重）+ 学号规则（年级/专业/序号）；保留 20250001 作为演练账号但改成拟真姓名 |
| 教师 | 9 人，最多 2 门课 | 扩到 12–15 人：3 人教 3 门课（跨班），其余 1–2 门；每人 1–3 个教学班 |
| 班级/专业 | 部分占位 | 行政班 6–8 个、班级人数 30–45，专业名与课程对应 |
| 课程 | 5 门 | 扩到 8–10 门，覆盖「基础课 / 专业核心 / 实践课」三类（课程因子才有区分度） |
| 学期历史 | 只有 term 4/5/8 | 补 2–3 个历史学期（含挂科率、教师尺度、分数序列），趋势与同比才有数据 |

### B2. C 通道校准（让"跨班可比"看得见）

**现状问题**：C 通道已生效（524/540 行），但均分 16.8、几乎全绿，看不出可比性；C1 消融里「历史挂科率因子 0.0%」是因为数据里没有真实的历史挂科差异。

**v3.0 要做**：
1. **构造教师松紧差异**：同课程不同班，同一评分项的平均分差 5–12 分（模拟"松老师/严老师"），让 `teacher_style.delta` 有真实取值与收缩过程。
2. **构造课程难度差异**：不同课程历史挂科率 3%–25%，让 `course_factor` 真正区分（0.9–1.15 区间）。
3. **构造班内异质性**：同班内前 20% 与后 20% 分差拉开，B 通道才有意义。
4. **熔断与样本不足**：留 1–2 个班样本量 < 10，触发熔断，演示"不敢算"的诚实路径。
5. **校准可视化页**（教师/教务端）：Δ 的原始值 vs 收缩后值、λ 与样本量、课程因子与历史挂科率散点、熔断清单。
6. **重跑 C1/C2**：用新数据做消融与阈值扫描，产出论文可用的对照表（现在这套数字要更新）。

### B3. 数据质量与口径

- 新增 `v3.0/sql` 数据校验脚本：分类合计 = 样本数、无孤儿选课、无重复判定、学期口径一致。
- 写一份《口径说明 v3.0》：判定公式、三通道、分档线、因子定义、统计指标定义（每个指标给 SQL）。

## 三、轨道 C：AI 亮点深化（从"能生成"到"能证明它值得用"）

| 亮点 | 内容 | 为什么值得做 |
|---|---|---|
| C1 Agent 多步分析 | 见轨道 A：给定问题自动组合多个工具取数 | 这是"多智能体"真正落地的地方，答辩最有说服力 |
| C2 报告 → 行动 | 报告里每个"重点关注学生"直接给「一键生成干预草稿（约谈提纲/补交清单）」 | 把"看完报告"接上"做完动作"，闭环才完整 |
| C3 RAG 评测看板 | 把 64 例盲评搬进界面：按课程/题型看命中率、拒答率、误拒率，可一键重跑 | 让"检索好不好"变成可持续观察的指标，而不是一次性脚本 |
| C4 提示词版本与 A/B | 提示词存库（版本号），同一批事实用两版提示词各跑一次，对比结构合规率与对账一致率 | 论文里可以写"提示词迭代的效果"，也便于回滚 |
| C5 幻觉检测看板 | 统计"越界数字拦截数 / 对账不一致数 / 结构不合格数 / 降级率"，按周趋势 | 把 v2.0 的三道校验变成可观测的质量指标 |
| C6 成本与限额治理 | 按场景/教师统计 token 与成本，日限额、超限降级、成本看板 | 演示"能控成本"，也是真实上线的前提 |
| C7 个性化解释卡 | 依据学生画像（历史薄弱项、出勤习惯）调整措辞与推荐动作顺序 | 从"通用解释"到"对这个学生说" |
| C8 流式输出 | 报告/答疑改为 SSE 流式，首字 1 秒内 | 体验提升明显，工作量不大 |

**取舍建议**：v3.0 先做 C1、C2、C3、C5（四个能形成"可观测的 AI 质量"闭环），C4/C6/C7/C8 放到 v3.1。

## 四、轨道 D：统计分析（v3.0 的另一大核心）

### D1. 指标体系（先定义，再画图）

| 分组 | 指标 | 口径 |
|---|---|---|
| 规模 | 学生数、选课数、覆盖班级数、数据完整率 | 按学期 |
| 风险分布 | 红/橙/黄/绿人数与占比、环比变化率 | 按班/课程/学院 |
| 预警效能 | 预警总数、未关闭数、关闭率、平均处置时长、超时未处理数 | 按周 |
| 干预成效 | 干预人数、干预后等级下降人数与比例、两周复评改善率 | 以"干预前等级 vs 复评等级"计 |
| 学习成效 | 平均分趋势、及格率趋势、作业提交率、课堂测试正确率 | 按周/按题型 |
| 课程/班级对比 | 同课程各班、同班各课程、教师间 | 红黄灯人次、平均分、最低分 |
| AI 质量 | 报告数、来源分布（DIFY/LLM/TEMPLATE）、对账通过率、拦截数、token/成本 | 按周 |

### D2. 数据与接口

- **物化快照表**（关键，避免实时聚合拖慢页面）：
  `stat_daily_class`（班级×日期：人数/红橙黄绿/平均分/预警数）、`stat_weekly_kpi`（周度汇总）、`stat_intervention_effect`（干预成效）
  每日定时任务 + 手动重算按钮。
- 接口（统一前缀 `/api/stats`）：
  `overview`（卡片）、`trend?metric=&from=&to=&groupBy=`（折线）、`distribution`（分布）、`compare`（多对象对比）、`funnel`（预警→干预→复核漏斗）、`effect`（干预成效）、`export`（CSV/Excel）。
- **变化率与同比**：统一返回 `current / previous / deltaRate`，前端直接画"双轴折线 + 变化率标签"。

### D3. 前端看板（教师 / 辅导员 / 教务三套）

- 引入 **ECharts**（按需引入，避免包体过大）：折线（趋势+变化率）、堆叠柱（红橙黄绿）、漏斗（闭环）、散点（Δ vs 松紧、因子 vs 挂科率）、热力图（课程×周）。
- 教师端：我的班（趋势、薄弱题型、报告/干预数）
- 辅导员端：我的班（风险变化、多门预警学生、干预成效）
- 教务端：全景（覆盖率、预警处置率、课程因子校准、AI 质量）
- 每张图配「口径说明」气泡（点开显示 SQL/定义），避免"图好看但说不清口径"。

### D4. 验收

- 任一图表的数据能一键导出，并与 SQL 直查结果一致（脚本断言）。
- 趋势图至少 8 个周点；干预成效漏斗的四段（预警→约谈→复评→改善）都有真实数据。
- 教务看板首屏加载 < 2 秒（物化表，非实时聚合）。

## 五、里程碑与排期（建议 4 个迭代，共约 4–5 周）

| 迭代 | 内容 | 产出（可验收） |
|---|---|---|
| **v3.0-α（1 周）** | 轨道 B 打底：拟真数据扩量 + C 通道校准 + 数据校验脚本 + 口径说明 | 12–15 名教师、8–10 门课、2–3 个历史学期；C1/C2 重跑出新表；校准可视化页雏形 |
| **v3.0-β（1.5 周）** | 轨道 D：指标定义 → 物化表 + `/api/stats` 六个接口 → 教师/辅导员看板（ECharts 3–4 张图） | 趋势/分布/对比/漏斗可点；导出与 SQL 一致 |
| **v3.0-γ（1.5 周）** | 轨道 A：工具注册 + 规划循环 + 护栏 + 留痕；20 个问题集评测 | Agent 问答页；工具选择正确率、数字一致率、时延达标 |

## 六、风险与取舍

| 风险 | 影响 | 应对 |
|---|---|---|
| Agent 跑飞/乱调用工具 | 耗时、成本、说错话 | 工具白名单 + 步数/token 上限 + 只读 + 数字对账（护栏先于功能） |
| 拟真数据改动大，破坏现有演示 | 答辩现场翻车 | 数据脚本独立成 `v3.0/sql`，可一键回滚到 v2.0 快照；改动前后跑一次验收脚本 |
| 统计口径不统一 | 图与报告对不上 | 指标先写定义 + SQL，再写接口；导出断言 |
| ECharts 包体/首屏 | 页面变慢 | 按需引入 + 物化表 + 懒加载 |
| 范围膨胀 | 做不完 | v3.0 只做 A1/A3、D1–D3、C1/C2/C3/C5；C4/C6/C7/C8 明确推迟 |

## 七、需要你拍板的 5 件事

1. **Agent 路线**：自研编排（推荐）还是接 Dify Agent？还是两条都做（自研为主、Dify 作为可选通道）？
2. **数据拟真度**：学生姓名用中文拟真姓名（推荐）还是保留学号为主、姓名脱敏为「张同学」？
3. **教师/课程规模**：扩到 12 名教师 / 8 门课够不够？还是要更像一个学院（30 名教师 / 20 门课）——注意演示数据量大会拖慢判定重算。
4. **统计首屏给谁看**：教师/辅导员/教务三套都做，还是先做辅导员+教务（汇报时最能体现"预警成效"）？
5. **历史学期**：补几个？我建议 3 个（足够画同比与"干预后是否改善"）。
