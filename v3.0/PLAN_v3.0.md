## 二、轨道 A：Agent 平台化（四角色 + 记忆 + 双实现）

### A1. 契约层：ToolSpec 单一来源

一份 `tools.yaml`（或 JSON）定义全部工具，**同时生成**：本地工具注册表 + Dify 自定义工具的 OpenAPI 3.1。

```yaml
- name: getClassRiskStats
  description: 查某教学班本学期的风险分布与未关闭预警数
  read_only: true
  timeout_ms: 3000
  params:
    teachingClassId: { type: integer, required: true }
    termId: { type: integer, required: false }
  returns:
    studentCount: integer
    red: integer
    yellow: integer
    green: integer
    hardFail: integer
    activeAlertCount: integer
    avgScore: number
```

**约定**：所有工具只读、返回结构化 JSON、单次 <3s、字段名与 `vo` 层一致（减少二次转换）。

### A2. 工具清单（9 个，v2.0 已有能力 + 2 个新增）

| # | 工具 | 来源 | 备注 |
|---|---|---|---|
| 1 | `getClassRiskStats` | 教师端总览 | 现有 |
| 2 | `getRiskTrend` | **新增（统计模块）** | 按周的风险分与等级序列 |
| 3 | `getCourseCompare` | 课程报告事实包 | 现有 |
| 4 | `getStudentRisk` | 预警详情 | 三通道依据 |
| 5 | `getInterventions` | 干预模块 | 按学生/班级 |
| 6 | `retrieveCourseDocs` | RAG | 带文档名/段号 |
| 7 | `getAlertExplain` | 解释卡 | 复用四段 |
| 8 | `getStudentMemory` | **新增（记忆）** | 长期画像摘要 |
| 9 | `draftIntervention` | **新增（草稿）** | 只生成草稿，不落库 |

### A3. 四角色编排（一次运行最多 4 步工具调用）

```
问题 + 上下文
   ↓
[Planner] 决定下一步调哪个工具（输出：tool + 参数 + 理由）
   ↓
[Executor] 执行工具（白名单 + 参数校验 + 超时 + 留痕）
   ↓
[Critic] 证据够不够？
   ├─不够 → 回到 Planner（最多 4 步）
   └─够   → 交给 Writer
              ↓
          [Writer] 结论 + 3 条动作 + 依据（引用记忆与检索片段）
              ↓
          校验层（结构 / 数字白名单 / 定向对账）→ 通过则发布，否则降级
```

**每个角色的独立验收**（做不到就合并，不许当花瓶）：

| 角色 | 验收 |
|---|---|
| Planner | 30 题中 ≥20 题的第一步工具选择合理（人工标注对比） |
| Executor | 工具调用成功率 100%；非法参数 100% 拦截 |
| Critic | 10 个"信息不足"用例中 ≥8 次正确要求继续取证；不得空转（连续两步调用同一工具同一参数即判失败） |
| Writer | 结构合规 100%、数字一致 100%、动作可执行（含具体对象与频次） |

### A4. 记忆设计（跨会话、跨学期）

**两层表**：

| 表 | 作用 | 关键字段 |
|---|---|---|
| `student_memory` | 一学生一行的"长期画像" | 学生、更新时间、薄弱分组 Top3、出勤习惯标签、干预次数、最近一次干预结论、风险等级变化趋势（近 3 次判定）、embedding（可选） |
| `student_memory_event` | 追加式事件流 | 学生、事件类型（判定/干预/复评/问答）、摘要、来源 id、时间 |

**写入时机**：判定完成后（风险等级变化）、干预登记后（结论摘要）、学生问答后（关注点）。**只写摘要，不写原文**（隐私与成本）。

**读取方式**：`getStudentMemory(studentId)` 返回压缩后的 300 字以内摘要，供 Writer 在"针对这个学生说话"时引用。

**验收**：同一学生隔天再问"我该先补什么"，答案必须体现上次干预结论，且不再重复询问已知信息（如"你哪门课最弱"）。

### A5. 观测与轨迹页

- `ai_run` / `ai_run_step` 扩展：`provider`（LOCAL/DIFY）、`step_role`（PLANNER/EXECUTOR/CRITIC/WRITER）、`tool_name`、`args_digest`、`result_digest`、`gate_status`
- **Agent 轨迹页**（0.5–1 天）：左问题 + 最终答案，右时间线（每步：角色、工具、入参、返回摘要、耗时、校验），顶部：步数/耗时/token/provider/是否降级
- 指标看板：工具选择正确率、步数分布、降级率、P95、单次成本

### A6. 评测集（30 题，一条命令跑完）

| 类型 | 题数 | 例 |
|---|---|---|
| 单生诊断 | 6 | "周敏为什么红灯？" |
| 班级趋势 | 6 | "计算机1班这周红灯为什么变多？" |
| 跨班对比 | 5 | "数据结构三个班谁最吃力？" |
| 干预成效 | 5 | "上个月约谈过的学生后来怎么样了？" |
| 记忆类 | 4 | "我上次说先补什么？"（需 ≥2 步 + 记忆） |
| 应拒答 | 4 | "帮我查隔壁班李老师的学生"（越权）、"预测我期末考多少分"（无法断言） |

产出：`eval/agent_eval.json`（每题期望工具链、期望包含/排除的数字）+ 对比报告（LOCAL/DIFY）。

## 三、轨道 B：数据层（P0，先做）

### B1. 必修 Bug

| 问题 | 现状证据 | 修法 |
|---|---|---|
| `course_factor` 全 NULL | `course_fail_rate_history` 5 行，`factor` 均 NULL、`is_initialized=0` | 补初始化：`factor = clamp(1 + k*(fail_rate - baseline), 0.90, 1.15)`，写回 `is_initialized=1`，并在引擎读取处加兜底（NULL 时按 1.0 且记 WARN） |
| Δ 收缩"假生效" | `shrink_lambda` 全 0.620、`sample_size` 全 45 | λ 随样本量变化（如 `λ = n/(n+k)`，k 按评分项方差估），小样本收缩更狠 |
| 无熔断案例 | `fused` 全 0 | 留 1–2 个班样本 <10，`fused=1` + 原因，演示"不敢算" |

### B2. 拟真数据（参数化 + 可复现 + 可回滚）

| 参数 | 目标 |
|---|---|
| 教师 | 12–15 名，其中 3 人教 3 门课（跨班） |
| 课程 | 8–10 门（基础/专业核心/实践三类） |
| 行政班 | 6–8 个，30–45 人 |
| 学期 | 当前 + 3 个历史学期 |
| 班间平均分差（同课程） | 6–12 分（严师/松师） |
| 班内 sd | 9–12 |
| 课程挂科率 | 3%–25% |
| 姓名 | 中文拟真姓名库（去重），保留"周敏/杨娜"等已有角色一致 |
| 保留叙事 | 02 班最吃力、重修班黄灯多 |

### B3. 工程要求

- `v3.0/sql` 独立目录；每个脚本幂等；提供 `snapshot_v2.0.sql`（回滚用）
- 生成器带 `seed`，同参数同结果；参数写在 `v3.0/sql/seeds/params.json`
- 数据校验脚本：分类合计=样本数、无孤儿选课、无重复判定、三通道字段非空率、效应量抽样断言

## 四、轨道 D：统计（先辅导员 + 教务）

### D1. 五个闭环指标（先定这两个看板够用）

1. 预警关闭率（周期内关闭数 / 新增数）
2. 平均处置时长（创建→关闭，小时）
3. 干预后等级下降比例（干预前 vs 两周复评）
4. 两周复评改善率
5. 风险面变化率（红黄灯占比环比）

辅助指标：预警总量、超时未处理、多门预警学生数、课程集中风险 Top5、覆盖率（数据完整率）。

### D2. 物化快照表（避免实时聚合）

```sql
stat_daily_class(id, stat_date, teaching_class_id, student_count, red, orange, yellow, green,
                 avg_score, alert_new, alert_closed, intervention_count, engine_version)
stat_weekly_kpi(id, week_start, scope_type, scope_id, metric, current_value, prev_value, delta_rate)
stat_intervention_effect(id, week_start, teaching_class_id, intervened, improved, unchanged, worsened)
```

每日定时任务 + 手动重算按钮；重算幂等。

### D3. 接口（`/api/stats`）

`overview` / `trend` / `distribution` / `compare` / `funnel` / `effect` / `export`（CSV/Excel）。统一返回 `current / previous / deltaRate`。

### D4. 看板

- **辅导员端**：我的班风险趋势（折线+变化率）、多门预警学生变化、干预成效漏斗、班级对比柱状
- **教务端**：全院覆盖率与处置率、课程集中风险 Top5、课程因子校准散点（挂科率 vs factor）、预警处置时效分布、AI 质量（对账/降级）小卡片
- 每张图配「口径说明」气泡（显示定义与 SQL）

## 六、Dify 双实现（本机）

1. **本机部署**：复用 `v2.0/ai/dify`（docker），端口与 v2.0 一致（8090）；启动脚本化，一条命令拉起
2. **工具导入**：由 `ToolSpec` 生成 `tools.openapi.json` → Dify「自定义工具」导入
3. **Agent 应用**：建 **Agent 应用**（非普通工作流），system prompt 与本地一致，工具选 8 个只读工具；inputs 仅 `teachingClassId`、`question`、`studentId?`
4. **输出契约**：要求返回 JSON `{answer, actions[], evidence[]}`；`DifyAgentProvider` 做与本地一致的校验
5. **Parity 测试**：30 题双跑，出对比表（关键数字一致/方向一致/步数/耗时/成本）
6. **演示备份**：录制 1–2 分钟画布运行视频；现场 Dify 异常则放视频并讲降级

## 八、风险与对策

| 风险 | 对策 |
|---|---|
| 双实现分叉 | ToolSpec 单一来源；parity 测试进回归；改契约必须同时更新 Dify 插件 |
| 多智能体变"多次调用" | 四角色各自独立验收，不达标即合并 |
| Critic 空转 | 连续两步同工具同参数判失败；步数上限 4 |
| 数据改造破坏 v2.0 演示 | 独立 `v3.0/sql` + 快照回滚；改造后先跑 v2.0 验收脚本 |
| Dify 现场不可用 | 本机 docker + 视频备份 + 降级到 LOCAL |
| 记忆写坏/膨胀 | 只写摘要；单学生摘要 ≤300 字；事件表按月归档 |
