# 学情预警系统 v2 · 第二阶段演示脚本（学情预警主线）

> 用途：答辩 / 验收时按顺序演示，全程用真实接口与真实数据，每一步都能给出可复算的数字。
> 时间：约 8 分钟；账号口令统一 `000000`。
> 环境：后端 `http://127.0.0.1:8080`（演示可另起 18080），前端 `npm run dev` → `http://localhost:5173`。
> 一键跑通（只读为主，可重复执行）：`powershell -NoProfile -File v2.0\tool\demo_stage2.ps1 -Base http://127.0.0.1:18080`
> 需要重置成演示初始状态：`powershell -NoProfile -File v2.0\tool\rebuild_demo.ps1`（含重建库、判定、演示痕迹与导学发布）

## 0. 先讲清一句话口径（30 秒）

> 先看**缺课**：一学期有效课次 ÷ 3 向下取整就是允许缺课次数，超过即**硬性不合格**；
> 再看**成绩**：`T = 课程加权分 W − 扣分 P`（`P = 2×缺课 + 1×迟到 + 1×超出 3 次的请假`）；
> 两条合起来给风险分与红 / 橙 / 黄 / 绿四级。置信度不够时只提示行为风险，不给分数结论。
> **学生端只给结论与建议**，教师的处置记录属于内部工作记录；有疑问可以申诉一次。

## 1. 教务端：口径是可配置的版本（`/admin/rules`）

1. 登录 `admin001` → 导航「规则配置」。
2. 指出页面上半部分：当前生效版本 `v2.0.0`，阈值 **红 75 / 橙 60 / 黄 40**，扣分 **2 / 1 / 1**，请假免扣 3 次，期末满分 100，覆盖率阈值 33.3%，置信度下限 0.15。
3. 指出下半部分「版本历史」：改规则不是改老版本，而是**新增版本并生效**，老版本可回切；每次判定都会把引擎版本写进 `risk_state`，所以能回答"这次等级变化是哪一版规则造成的"。
4. 铺垫一句：版本 2 是演示用的收紧版本（70 / 55 / 35），当前**未启用**。

> 若现场想证明规则真的会改结论：点「调整规则」把阈值改成红 60 / 橙 45 / 黄 25 → 保存并生效 → 点「按当前规则重新判定本学期」，
> 会出现"等级变化 N 条"；演示完点历史版本 `v2.0.0` 的「切换到此版本」再重判一次即可还原。

## 2. 教师端：预警监控（`/teacher/monitor`）

1. 登录 `1001`（李兑，教学班 CS-01-A 大学计算机基础，12 周课）→ 导航「预警监控」。
2. 总览 7 个数字：**红色 1（处理中）/ 黄色 4**、待处理 4、待核实申诉、已判定 45 人，右侧是引擎版本与最近判定时间。
3. 名单：按风险分倒序，一条一人一课；列里有**缺课额度 `6 / 4 / -2`（已缺 / 允许 / 剩余）**、`期末需考 67.9`（12 周课允许缺 4 次）、触发规则（缺课超限 / 缺课接近上限 / 加权分偏低）。
4. 点「详情」打开右侧抽屉，讲四块内容：
   - **三通道证据**：A 行为硬线（缺课 vs 上限，是否已超限）、B 加权分与班内排名、C 学业增量（第二阶段未启用，留给第三阶段）。
   - **判定依据**：`缺课 6 次，已超过允许上限 4 次（缺课超 1/3 直接挂科）`。
   - **关联考勤与成绩** + **建议**。
   - **时间线**：生成 → 通知 → 认领 → 记录处理 → 关闭。
5. 演示处置闭环：点「提醒学生」→ 学生端收到消息；点「认领」→ 状态变「处理中」；填处理内容 → 「记录处理」→ 时间线多一条。
   （若这条例已关闭，换名单里任意一条「待处理」的。）6. 演示批量能力：勾选几条 → 「批量提醒」；点「导出名单」得到 xlsx（字段与列表一致）。
7. 演示申诉：名单里带「申诉」标记的那条（学生 `20250001`，红色），详情里能看到学生原文"第六次缺课当天在校外参加学科竞赛，带队老师可证明，申请按公假处理"，核实后记录处理或关闭。
8. 讲一句幂等与冷却：连续点两次「重新判定」不会重复生成预警（`新增 0 / 等级变化 0`）；人工关闭或忽略后，同等级风险 7 天内不再重复告警。

## 3.8 批改与项目评分：独立弹窗

1. 教师 `1001` →「教学详情 → 测验 / 作业」→ 某张卷子「交卷与批改」→ 列表里点某位学生的「批改」：
   **弹出独立批改窗口**（不再把面板展开在列表下面），窗口里逐题显示题面、学生作答、参考答案，填空/简答可直接给分与写评语；
   底部有「← 上一份 / 下一份 →」、跳到未批、整卷批注与「提交批改」，提交后同一窗口给出「✓ 批改完成 · 总分 X 分」，Esc 关闭。
2. 教师 `1004` →「教学详情 → 项目」→ 打开一个项目 → 某条提交点「评分」：
   弹出评分窗口（文件、仓库链接、成员占比与个人得分、项目总分、评语），保存后窗口内即时刷新分数，列表同步。
3. 口径：项目团队分按 `团队得分 × 个人占比 × 组员数` 折算个人得分（等分时等于团队分，封顶 100）；测验只提交填空/简答的分数，客观题由系统判分不可改。

## 5. 常见追问与回答

- **为什么他缺课 6 次就红色？** 12 周课只有 12 次课，允许缺 4 次，缺 6 次已过线；A 通道硬线优先，直接判红（`A_HARD_LINE`），B 通道只用于没有硬线时的分级。
- **期末需考 59.6 是什么意思？** `x = (及格线 + 扣分 − 其余项加权) ÷ 终结性权重`；比如四史概述平时 60% 拿了 68 分（折 40.8），终结性占 40%，期末就要考 48 分以上，若平时只有 60 分则要考 60 分。
- **改了阈值会不会造假？** 不会：规则版本化 + 审计留痕，`risk_state` 记录引擎版本，任何一次等级变化都能回放到具体版本与判定时间。
- **为什么学生看不到老师记了什么？** 学生端只给结论与建议；教师处置记录属于内部工作记录，进 `intervention_record`，学生侧时间线只保留结论性节点。
- **置信度是什么？** 考勤覆盖率 × 成绩完整性 × 样本量；覆盖率低于 1/3 或置信度低于阈值时，只输出「仅行为预警」，不给分数结论。
- **为什么没有 AI？** 第二阶段按口径冻结，判定全为确定性算法，可复算、可对账；大模型解释与建议放在第三阶段，只解释不参与数值判定。
- **课堂测试/作业的数据从哪来？** 来自「测验与作业」里的试卷：每份卷都绑定了评分项（`scheme_item_id`），成绩侧按各次均分自动汇总（教师端矩阵里标 `AUTO`）。
- **团队项目的个人分怎么算？** `个人得分 = 团队得分 × 个人占比 × 组员数`，等分时等于团队分，占比高的按比例上浮（封顶 100）；个人项目占比按 100% 计。
- **申诉回复在哪看？** 教师回复即写入 `teacher_reply` 并给学生发 `ALERT_REPLY` 消息，学生端「学情预警」的申诉区与课程卡片会直接显示「老师已回复」。
