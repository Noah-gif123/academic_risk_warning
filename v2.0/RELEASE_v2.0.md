## 一、这一版的范围

四端（学生 / 教师 / 辅导员 / 教务）的课程全过程学情管理：数据采集 → 规则判定 → 预警生成 → 处置闭环 → 效果复核，
并在「解释与建议」环节接入大模型，形成三份群体报告与六类 AI 能力。

| 层 | 内容 |
|---|---|
| 数据 | 60 张表；判定子系统 13 张核心表（快照 / 事件 / 留痕分层）；39 个 SQL 脚本可重建演示库 |
| 判定 | 引擎 v2.1.0：A（硬门槛）/ B（班内相对）/ C（跨班可比）三通道，`riskScore = clamp100(max(clamp100(base×factor), guardFloor))`，75/60/40 分档 |
| 预警 | 判定与预警分离；预警幂等、可升级、可通知；处置动作（约谈 / 补交 / 上报）全程留痕 |
| AI | 六个场景：学生报告、群体报告（教学班 / 行政班 / 课程三种口径）、预警解释卡、出题、批改、课程问答 |
| RAG | MySQL ngram 全文 + bge-m3 向量双路召回，RRF（k=60）融合 + 闸门过滤（拒答而非硬凑） |
| 工程 | Spring Boot 4.0.6 + Java 17 + MyBatis-Plus + MySQL 8；Vue 3 + Vite + Tailwind；四端角色注解 + 服务端数据范围校验 |

## 三、关键指标（均为本机实测）

| 指标 | 结果 | 出处 |
|---|---|---|
| 判定规模 | 540 条课程级判定（红 16 / 橙 3 / 黄 100 / 绿 421） | `risk_state` |
| 单测 | 25 / 25 通过（RiskMath 20 + TriggerGate 5） | JUnit |

| RAG 盲评（64 例） | 混合检索 recall@4 = 1.0、MRR 0.9491、nDCG@4 0.9621；不可答拒答 0.90、可答误拒 9.3% | `rag-blind-eval.ps1` |

## 五、已知不足（如实记录）

1. **未做压测**：只有单请求耗时（报告 3.8–14 秒），无并发数据与容量规划。
2. **未接 CI**：构建与回归靠本地脚本；出题闸门单测因离线仓库缺 Mockito 未纳入回归。
3. **知识库覆盖有限**：5 门课 29 篇资料，部分报告的依据仍落在「导学第 1 段」。
4. **姓名进提示词**：报告“重点关注名单”为可读性使用姓名，演示为合成数据；真实部署前需改脱敏编号。
5. **并发防护缺失**：重复点「生成报告」会产生多份历史记录（不覆盖旧数据）。
6. **演示数据一致性**：`42_seed_grading_demo_paper.sql` 建的三份提交是可评样本，其余 42 份简答仍是占位文本（分数未动），现场不要随手点。
