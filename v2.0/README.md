## 三、怎么改、怎么重新生成

约定：**数据只有一个来源**。
`工具/cases.json` 保存全部用例（编号、名称、参与者、摘要、前置/后置/事件流/备注）；
用例图的椭圆、docx 中的表2.1 摘要表与表2.2～2.24 详细表**都由它生成**，改一处即可同步。
同理，ER 图由 `工具/mker.js` 内的表与字段定义生成，流程图/状态图/时序图由 `工具/mkflow.js` 生成，
正文文字与图表插入位置在 `工具/doc_content.json`。

```powershell
# 0) 依赖：Node.js；生成 Word 需要全局包 docx（一次性）
npm i -g docx

# 1) 改完 工具/cases.json 后重建分角色用例图（自动排版）
node 工具\mkuc.js

# 2) 改完 ER / 流程图定义后重建（mker.js 管 ER，mkflow.js 管活动图/状态图/时序图）
node 工具\mker.js
node 工具\mkflow.js

# 3) 自检：所有图形是否超出画布
node 工具\check.js

# 4) 生成 SVG（同时输出 .drawio）
powershell -File 工具\build.ps1

# 5) 渲染 PNG（需要本机 Chrome；在受限沙箱里 Chrome 起不来，请在普通命令行执行）
powershell -File 工具\build.ps1 -Png

# 6) 生成 Word
node 工具\build_docx.js
```

说明：
- `工具/render.js` 是自写的 SVG 渲染器，把 JSON 描述的形状、连线、泳道、实体框、类框、时序图渲染成图，**不依赖 graphviz / mermaid**，因此完全离线可重跑。
- 图片按 A4 正文区（约 16 cm）自动等比缩放，不会被裁切；表号在生成时自动连续编号（正文里的“如表2.x所示”会跟着一起变）。
- `-Only "f2*"` 可以只重建名称匹配的图，避免全量重跑。

## 六、已知限制

1. 图由脚本生成，版式统一但不如手工 Visio 精细；如需微调，请用 `图源/drawio/*.drawio` 改后重新导出替换。
2. Word 的最终分页效果无法在生成端验证（本机没有 Word/LibreOffice），图与表已按 A4 正文宽度设计，若出现跨页断裂可手工调整段落位置。
3. 用例与流程按 v2 设计写全，其中教务端、辅导员端、问卷与双轨考勤等部分尚未编码实现——这是既定选择（先定文档与数据库，再实现）。
