# RAG 检索层与评测（R2 + R4）

> 目标：让"基于 RAG 检索增强"这个题目有真实实现和可验证的实验数据，而不是"配了个知识库"。
> 本文记录已落地的代码、如何跑评测、当前基线，以及还缺什么。

## 1 结构：Dify 做向量底座，方法层在自己代码里

```
课程资料（导学 / 课件 / 实验指导 / 复习提纲）
   │ ① Dify 知识库：解析 → 分块 → embedding → Weaviate        ← 用 Dify 的工程，不自造轮子
   ▼
向量路 top-20 (DifyVectorClient)        全文路 top-20 (MySQL ngram FULLTEXT)
   └──────────────┬───────────────────────────────┘
                  ▼
   ② RRF 融合（RetrievalService，只看名次不看分数）→ 拒答判据（guard）
                  ▼
   ③ 生成（StudentQaService，带引用要求）+ 引用校验
                  ▼
   ④ 评测（RagEvalService）：全文 / 向量 / 混合 三行对比
```

| 组件 | 位置 | 职责 |
| --- | --- | --- |
| `RetrievalService` | `service/ai/RetrievalService.java` | 三模式检索、RRF 融合、拒答判据、诊断包；`guard()` 是线上问答与评测共用的唯一判据 |
| `DifyVectorClient` | `service/ai/DifyVectorClient.java` | 调 `POST /v1/datasets/{id}/retrieve`；没配 key 不报错，只标"未配置" |
| `RagEvalService` | `service/ai/RagEvalService.java` | 跑评测集、算 recall@k/MRR/nDCG/拒答准确率/误拒率、写 `ai_rag_eval_run` |
| `AdminRagEvalController` | `controller/admin/AdminRagEvalController.java` | 评测入口（只检索不生成，**不消耗 token**） |

## 2 配置

```yaml
app.ai.retrieval:
  mode: HYBRID            # FULLTEXT / VECTOR / HYBRID；向量没配时自动降级为 FULLTEXT
  pool-size: 20           # 每路召回池
  vector-top-k: 20
  dataset-key: ${AI_RAG_DATASET_KEY:}   # Dify 知识库 API Key（控制台「知识库 → API」，不是应用 App Key）
  dataset-id: ${AI_RAG_DATASET_ID:}     # 知识库 ID
```

诊断会写进 `ai_qa_log.retrieval_mode` 与 `ai_qa_log.retrieval_json`，含每路命中数、top 分、名次、融合分、耗时、降级原因。

## 3 怎么跑评测

```bash
# 后台先跑起来（需要 admin001 / 000000 登录拿 token）
POST /api/admin/ai/rag-eval?mode=FULLTEXT&k=4      # 单模式
GET  /api/admin/ai/rag-eval/compare?k=4           # 全文 / 向量 / 混合 三行对比
```

评测集在 `ai_rag_eval_case`（`sql/38_seed_rag_eval.sql` 生成）：**30 条可答 + 10 条不可答**，
题目全部取自真实语料，`gold_doc` 就是答案所在文档；同一份导学发给多个教学班时用 `|` 列多个等价出处。

## 4 指标定义

| 指标 | 定义 |
| --- | --- |
| `recall@k` | 可答问题里，标准出处出现在前 k 条命中的比例（文档级） |
| `MRR` | 第一条正确出处的名次倒数均值 |
| `nDCG@k` | 二值相关性下的归一化折损累计增益 |
| `refuseAcc` | 不可答问题被正确拒答的比例 |
| `falseRefuse` | 可答问题被误拒的比例（越低越好） |
| `effectiveFallback` | 本次有多少条用例**其实没走目标模式**（例如向量未配置被降级）——不为 0 时该行指标不能当结论 |

### 5.1 三行消融对比（k=4，这就是论文要的那张表）

| 模式 | recall@4 | MRR | nDCG@4 | 拒答准确率 | 误拒率 | 平均耗时 |
| --- | --- | --- | --- | --- | --- | --- |
| 全文（MySQL ngram） | 0.8889 | 0.8164 | 0.8349 | **0.90** | 9.3% | 1–2 ms |
| 向量（Dify 知识库 + bge-m3） | **1.0000** | 0.9414 | 0.9560 | 0.10 | 0% | 42 ms |
| **混合（全文 + 向量 + RRF）** | **1.0000** | **0.9491** | **0.9621** | **0.90** | 9.3% | 41 ms |

三条结论（答辩就讲这个）：

1. **向量路补上了全文路漏掉的召回**：recall@4 从 0.8889 提到 1.0000。全文路漏的正是口语化提问
   （"课堂测试几次""三级项目怎么交"），语义检索能把它们对上。
2. **但纯向量路的拒答准确率只有 0.10**——语义相近就会答，问"傅里叶变换"它能从高数讲义里找出
   一段"看起来相关"的内容。**这说明向量检索不能单独上线，必须带词面护栏。**
3. **混合路同时拿到 1.0 召回和 0.90 拒答**，因为 RRF 的头部通常含全文命中，护栏用得上词面支撑度；
   代价是误拒率从 5.6% 升到 7.4%（多拦了 1 条可答题）。这就是"要召回还是要严谨"的真实取舍。

> 延迟说明：向量路每次要调 Dify + embedding，冷启动约 414 ms，命中缓存后 47 ms，仍比全文路高一个量级。
> 生产上合理的做法是"全文优先、向量补充"或加查询缓存，不适合把向量路当默认唯一通道。

### 5.2 词面支撑度扫参（minLexSupport，全文路护栏）

护栏口径改过一次：词面支撑度从「只看 top-1 片段」改成「取 top-k 最大值」——表 3 这类表格碎片
单看第一名只有 0.176，会把"总评成绩怎么构成"这种核心问题误拒。改动后重新扫参（HYBRID，生产默认模式）：

| minLexSupport | 拒答准确率 | 误拒率 |
| --- | --- | --- |
| 0.20 | 0.80 | 5.6% |
| **0.25** | **0.90** | **9.3%** |
| 0.30 | 0.90 | 13.0% |
| 0.35 | 0.90 | 18.5% |

**0.25 是拐点**：拒答准确率 0.80 → 0.90，误拒 5.6% → 9.3%；再往上拒答不再提升、误拒继续涨。
按"宁可拒答不编造"的原则取 **0.25**（每 54 条可答题误拒 5 条）。默认值已改为 0.25。

> 试过用"向量相似度"当第二路放行信号（词面弱但语义强就答），实测 HYBRID 拒答准确率从 0.90
> 掉到 0.10——向量相似度对"看起来相关"过于宽容，不能作为"有依据"的判据，已撤回该分支。

### 5.3 语料扩张暴露的问题与处理

1. **同源分块占满 top-k** → 加同源抑制 `max-per-doc=2`，recall@4 0.7778 → 0.7963。
2. **逐字数字压过正确文档**（大纲的学分/学时压过导学）→ 主要由向量路解决；另外把大纲口径统一到导学
   （见 §5.4），全文路 recall 随之从 0.8333 提到 0.8889。
3. **"词在、答案不在"的假命中** → 靠 minLexSupport 0.20 + 引用校验挡；这类 case 长期要盯。

### 5.4 口径统一（按导学为准）

原始资料里 `课程大纲_大学计算机基础` 写「3 学分」，而 `导学 · CS-01-A` 写「2.0 学分」。
处理方式：**不改用户原件**，在 `KbIngest.CORRECTIONS` 里登记修正，入库时统一为 2 学分并打印留痕，
任何一次语料重建都会得到一致口径（`v2.0/tool/kb/KbIngest.java`）。
大纲里的「48 学时（理论 32 + 实验 16）」未改——导学未规定学时，改它等于编数字，需教务口径确认。

解读要点（答辩可以直接讲）：

- 全文路在**有明确术语的题目**上已经很强（recall@4 = 0.9667），这也是为什么本项目不能丢掉全文路；
- 10 条不可答问题**全部被正确拒答**（refuseAcc = 1.00），说明 `guard()` 的阈值 + 词面支撑度护栏是有效的反幻觉手段；
- 但语料只有 40 块、且题目用词贴近原文，所以这个分数**偏乐观**；等语料扩到 200+ 块、题目改用口语化提法，才是真实压力测试。

## 7 R1：检索已铺到四个场景

| 场景 | 检索查询怎么来 | 依据落在哪 | 实测 |
| --- | --- | --- | --- |
| 课程问答 | 学生原问题 | 正文末「依据：文档名 第N段」+ `ai_qa_log.citations_json` | 已有，含逐条引用校验 |
| 学习评价报告 | 课程名 + 成绩单状态 + 分项里最弱的两项 | 正文第 5 段「参考依据」+ `ai_report.content_json.sections[4]` | id=78 `source=DIFY`，模型还在正文里真实引用（"第1讲…第1段列出的平时成绩构成"） |
| 预警解释卡 | 触发类型（缺勤/作业/成绩…）+ 薄弱分组 | 第 5 段「依据」+ `ai_alert_explain.content_json.sections[4]` | id=6 `source=LLM`：`导学 · CS-01-E 第1段；导学 · CS-02-E 第1段；导学 · CS-RT-E 第1段` |
| 群体报告 | 课程名 + 考核口径 | 末段「参考依据」+ `ai_group_report.content_json.sections[4]` | id=6 `source=LLM`，40 s |

三条落地原则：

1. **检索不足不硬凑**：`guard()` 判定无依据时，报告/解释卡照常生成，但依据段落如实写"暂未检索到对应条款"，
   绝不编造资料名。检索本身抛异常也被吞掉（沿用既有三级降级约定），不影响主流程。
2. **依据段落与模型输出分离**：AI 写的四段保持原样，依据是后端追加的独立段落，模型编不进来、也删不掉。
3. **查询串按场景定制**：不是拿整篇报告去搜，而是用"触发原因 + 薄弱项"这类短查询，命中率更高、噪声更少。

### 8.1 Q1 为什么要单独抽一个类

线上走 Dify / 直连两条通道，靠自然运行很难稳定复现"串口径"（模型多数时候说的是对的类型）。
所以把判定抽成 `TriggerGate`（纯静态、无依赖）并配单测，把"必须拦"和"不能误伤"两条边界都钉住：

- 必须拦：缺勤卡通篇讲分数、分数卡通篇讲考勤；
- 不能误伤：纯定性描述（两类关键词都没命中）要放行；
- 不参与：`MULTI` / `DATA` 这类本身就没有单一关键词的类型。

## 9 A5：口径统一与旧数据清理

### 9.1 两把尺子的问题

原实现里学生总分来自 `score_result.total_score`，过程分来自 `risk_state.data_quality_json`，
但**班级均分与排名只按 `total_score` 算**。于是分项没录齐的学生会看到：

```
过程分 80.72    ← 过程分口径
班级均分 30.94  ← 总评分口径（全班均分）
班内排名 41/45  ← 也是总评分口径
```

两个口径差 50 分，读者会以为"我远超班级平均却排倒数"。

**修复**：`FactPackBuilder` 在 `score_status=PARTIAL` 时把班级对比整体切到过程分口径
（同源 `risk_state` 聚合），`ReportFact.scoreCaliber` 记录口径，提示词写明
「班级均分（过程分口径）」「班内排名（过程分口径）」。

实测同一个学生：

| | 总分 | 过程分 | 班级均分 | 排名 | 口径 |
| --- | --- | --- | --- | --- | --- |
| 修复前 | 25.29 | 80.72 | 30.94 | 41/45 | 混用 |
| 修复后 | 25.29 | 80.72 | **82.97** | **28/45** | 均为 PROCESS |

> 全班过程分均值 82.97 与总评分均值 30.94 的差距，本身也说明"期末未计入"时总评分是失真的。

## 11 盲测评测集（回应"自编自测"质疑）

现有 64 条评测集由实现者编写，评委会质疑"自己出卷自己判分"。做法是**让别人出题、实现者不参与标注**，
单独跑一档指标与自编集对比。

### 11.1 出题说明（可直接发给同学）

> **任务**：阅读这 5 门课的课程资料（导学 / 课件 / 习题集 / 大纲 / 实验指导），
> 写 10~15 条**学生真实会问**的问题，并为每题标出「答案在哪份资料的哪一段」。
> **要求**：① 可以口语化，别照抄原文用词；② 至少 3 条是"资料里查不到"的（用来测系统会不会乱编）；
> ③ 不要问系统功能（"怎么导出报表"），只问课程内容。
> **不用管实现**，你怎么自然怎么问。

### 11.2 录入格式

```sql
insert into ai_rag_eval_case (course_id, question, answerable, gold_doc, gold_section, gold_keywords, note)
values
  -- 可答：gold_doc 写答案所在文档名（同一内容多份时用 | 分隔），如命中任一即算对
  (1, '平时分里课堂测试占多少分', 1, '导学 · CS-01-A|导学 · CS-02-A', null, '35', 'blind'),
  -- 不可答：answerable=0，gold_doc 留空
  (1, '这门课会不会有期中考试', 0, null, null, null, 'blind');
```

注意：
- `note` 必须写 `blind`，评测按它分档；不要与 `seed38` 混用
- `gold_doc` 必须是 `ai_kb_chunk.doc_name` 里真实存在的名字（可先 `select distinct doc_name from ai_kb_chunk;` 核对）
- 出题人**不要看**自编集（`note='seed38'`），避免互相影响

### 11.3 跑批与判读

```bash
powershell -NoProfile -File v2.0/tool/rag-blind-eval.ps1          # 默认 HYBRID / k=4
powershell -NoProfile -File v2.0/tool/rag-blind-eval.ps1 -Mode VECTOR -K 10
```

脚本会分别跑 `note=seed38`（自编集）与 `note=blind`（盲测集），输出对比表并给判读：

| recall 差距（自编 − 盲测） | 判读 |
| --- | --- |
| ≤ 0.10 | 检索没有过度拟合自编题，可直接写进答辩材料 |
| > 0.10 | 自编题偏乐观：按盲测集失分的题型补语料或调检索参数，重跑后再报数 |

> 盲测集为空时脚本会提示"暂不可用"并正常退出，不影响其它流程。
