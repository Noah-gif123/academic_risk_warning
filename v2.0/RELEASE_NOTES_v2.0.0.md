## 🎯 学情预警与个性化学习管理系统 v2.0.0 — RAG + 多智能体

> 基于 **RAG 检索增强 + 多智能体协作** 的高校学情预警系统。
> v2.0 在 v1.1.0「可运行、可观测、可评测」的基础上，把重心从「算得出」推进到 **「讲得清、对得上账、失败能降级」**：
> 判定仍由规则计算，大模型只负责写结论与建议，所有数字必须能从事实包复算，且发布前逐项对账。

### ✨ 本版本亮点

**🧮 可复算的风险判定引擎 v2.1.0**
- 三通道判定：A（缺勤/迟到硬门槛）、B（班内相对位置）、C（跨班可比折算，教师尺度 Δ + 课程因子）
- `riskScore = clamp100( max( clamp100(base × factor), guardFloor ) )`，按 75 / 60 / 40 分档为红橙黄绿
- 判定结果作为**快照**落库并记录引擎版本，任何时间点都能复算；硬门槛走下限保护，不被高分掩盖

**📄 三种群体报告 + 数字对账（核心新增）**
- 教学班报告（一门课 × 一个班）、行政班报告（一个班 × 多门课）、课程报告（一门课 × 多个班）
- 三种口径由同一套事实聚合而来，人数与分类计数**可以互相加总对账**（如 45×3=135、红灯 1+2+1=4）
- 定稿前用 **14 条规则做定向对账**（红/黄/绿灯人数、平均分、及格线、预警条数…），不一致会在报告里显式标注并留痕
- 报告附「参考依据」（检索到的课程资料原文摘句）与「报告涉及的学生」（可点击跳到学生详情）

**🔍 事实驱动的 RAG 检索**
- 查询由「课程 + 最弱题型/分组」构造，检索不足再回退通用串
- 全文（MySQL ngram）+ 向量（bge-m3）双路召回，RRF（k=60）融合 + 闸门过滤（低分/低支撑即拒答）

**🤖 多智能体报告与三道校验**
- 单向三层降级：Dify 工作流 → 直连模型 → 规则模板，任一层失败都能出报告，来源字段随报告落库
- 三道闸门：结构校验（固定四段）、数字白名单、定向对账；输出被截断时按双倍预算重试一次

**✅ AI 批改与建议分**
- 教师端对整卷主观题一次调用生成建议分 + 逐维度扣分评语 + 给分依据
- 三道闸门：分数范围、评语不编造数字、参考要点存在；**AI 不直接改分**，教师「填入评分框 → 提交批改」才生效

**🔐 工程与权限**
- 四端（学生 / 教师 / 辅导员 / 教务）角色注解 + **服务端数据范围校验**：跨教学班、跨课程、跨行政班越权均返回 400
- AI 调用全留痕（`ai_run` / `ai_run_step`）：通道、token、耗时、校验结论可统计，降级率可追责

### ⚠️ 升级说明

1. **数据库**：按编号顺序执行 `v2.0/sql` 下的脚本；v1.1.0 之后新增的关键脚本：
   - `40_term_synthetic_flag.sql`（合成学期标记，对学生/导员/教师隐藏）
   - `41_seed_grading_eval.sql`（AI 批改可评样本：题干 + 四维评分标准 + 三档作答）
   - `42_seed_grading_demo_paper.sql`（完整演示卷 6 题 100 分，可反复重置）
2. **AI 配置**：`ai.env` 由 `application.yml` 的 `spring.config.import: optional:file:./ai.env[.properties]` 自动加载；
   **不配置也能启动**，此时 AI 能力自动降级为规则模板，报告仍可生成。
3. **构建方式**：本项目可在无 Maven/Gradle 的离线环境构建（`javac @javac-full.args` + 手动 classpath），详见 README。
