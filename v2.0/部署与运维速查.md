> 三句话版本：**MySQL(3306) → 后端(8080) → 前端(5173)** 起三个服务就能演示；AI 走"直连优先、Dify 可选"；
> 容器化交付在 `v2.0/docker-compose.app.yml`，宿主机 MySQL 与 Dify 通过 `host.docker.internal` 访问。

## 1 本机最快起法

| 顺序 | 做什么 | 命令 / 操作 | 验证 |
| --- | --- | --- | --- |
| 1 | MySQL | Windows 服务 `MySQL80`（开机自启） | `mysql -uroot -p` 能进 `study_warning_system_v2` |
| 2 | 后端 | IDEA 运行 `AcademicRiskWarningApplication`；或 `cd v2.0/backend && gradlew bootRun`；或 `java -jar build/libs/academic-risk-warning-2.0.0-SNAPSHOT.jar` | 开 <http://localhost:8080/api/ai/health> 返回 `"code":0` |
| 3 | 前端 | `cd v2.0/frontend && npm install && npm run dev` | 开 <http://localhost:5173/> 出现登录页 |
| 4 | Dify（可选） | 双击桌面「启动 Dify(8090)」，或 `powershell -File v2.0/ai/start-dify.ps1` | 开 <http://localhost:8090> 能进登录页 |

- 前端 5173 会把 `/api` 代理到 `127.0.0.1:8080`（见 `frontend/vite.config.js`），**后端换端口要同步改代理**。
- 演示账号：教师 `1001` / 学生 `20250001` / 辅导员 `C001` / 教务 `admin001`，密码都是 `000000`。
- 不启 Dify 也能演示：报告与解释卡退「规则生成」，答疑与出题需要直连模型（见 §2）。

## 2 后端环境变量（AI 相关，全部可空）

| 变量 | 作用 | 不配会怎样 |
| --- | --- | --- |
| `AI_ENABLED` | AI 总开关（默认 `true`） | 设 `false`：全站不调用外部服务，报告走规则模板 |
| `AI_LLM_BASE_URL` / `AI_LLM_KEY` / `AI_LLM_MODEL` | **通用直连通道**（任意 OpenAI 兼容端点：DeepSeek / DashScope / 本地 vLLM） | 答疑与出题会报"模型通道未配置"；报告/解释卡退模板 |
| `AI_DIFY_BASE_URL` | Dify 地址（默认 `http://localhost:8090`） | 只影响 Dify 通道探测 |
| `AI_REPORT_APP_KEY` / `AI_CHAT_APP_KEY` / `AI_ALERT_APP_KEY` / `AI_GROUP_REPORT_APP_KEY`（/ `AI_QUESTION_APP_KEY` 预留） | Dify 工作流 App Key | 走直连；直连也没配则退模板 |
| `AI_DAILY_LIMIT` | 每用户每日调用上限 | 默认 `30`；答辩当天想连讲多个班可设 `0` 关掉 |
| `AI_DASHSCOPE_KEY` | 旧 DashScope 通道（`AI_LLM_*` 的兜底别名） | 同上 |
| `DB_USERNAME` / `DB_PASSWORD` | 数据库账号（默认 `root` / `root`） | 起不来 |

### 2.0 密钥怎么让程序读到（三选一，推荐第 1 种）

| 方式 | 做法 | 适用 |
| --- | --- | --- |
| **① 交给 Spring 自动导入（推荐）** | 把 `ai.env` 放在 **`v2.0/backend/`（或项目根、或 `backend/`）**，直接 Run 即可——`application.yml` 里有 `spring.config.import: optional:file:./ai.env[.properties]`，会把 `KEY=VALUE` 当 properties 读进环境，`${AI_LLM_KEY:}` 等占位符随之生效 | **IDEA 直接 Run、`gradlew bootRun`、`java -jar`** 都适用，零配置 |
| ② 注入进程环境 | `powershell -NoProfile -File v2.0/backend/run-ai.ps1` | 想显式控制、或要看脱敏日志 |
| ③ Docker | 用环境变量透传（见 `docker-compose.app.yml`） | 容器化交付 |

> 注意两点：① `.env` 这个后缀 Spring 不认，所以导入路径必须写成 `xxx.env[.properties]`（`[.properties]` 是扩展名提示，少了它会被静默跳过）；
> ② 有没有生效看启动日志：出现 `[AI] 直连通道就绪：<baseUrl> / <model>` 就是成功了；出现「直连通道未配置」的 WARN 说明没读到。

其他可调项在 `backend/src/main/resources/application.yml` 的 `ai:` 段：`timeout-seconds`、`yuan-per-k-token`（成本估算单价）、
`model`（仅占位；实际写入 `ai_run.model` 的是按通道判定出的真实标签：Dify 记 `dify-workflow`、直连记真实模型名、模板记 `null`）。

### 2.1 学习评价报告工作流（Dify 侧）必须满足的 4 个条件

`AI_REPORT_APP_KEY` 指向的 Dify 应用是一个 **workflow** 应用，节点为 `开始 → LLM(写报告) → 结束`。实测踩过的坑：

1. **LLM 节点 `max_tokens` 必须 ≥ 4096。** 报告用的是推理型模型（如 `deepseek-v4-flash`），它会把思考过程以
   `<think>…</think>` 前缀塞进输出；若 `max_tokens` 只有 1600，思考就把预算吃满，返回体里只有思考块、没有正文
   （`finish_reason=length`），后端判定"不含四段标题"而整体降级。
2. **`开始` 节点的 `facts` 变量 `max_length` 建议 ≥ 8000。** 分项/分组/题型多的学生，事实包会超过 4000 字。
3. **结束节点输出的变量名用 `text`**（后端按 `text / result / output / report / answer` 顺序取正文）。
4. **prompt 里禁止让模型自造数字。** 后端会对正文做数字回验（前三段必须命中事实包，第四段允许计划量），
   越界就重试一次、再失败就换直连通道，`ai_run.error_message` 里会留"主通道降级说明：…"。

> 后端剥离推理块的处理在 `ReportComposer.stripReasoning`；Dify 返回 `<think>` 未闭合时也能按段落标题裁剪。
> 验证一次是否真的走了 Dify：`select source, model from ai_run order by id desc limit 5;` 期望 `DIFY / dify-workflow`。

> 密钥只走环境变量，不写库、不进代码、不进 git。

## 4 重启电脑后怎么恢复

1. MySQL80 一般自启，先确认在跑；
2. 起后端（8080）→ 起前端（5173）；
3. 要用 Dify 就双击桌面「启动 Dify(8090)」，等 1–2 分钟容器变 healthy；
4. 开一次 <http://localhost:8080/api/ai/health> 确认 `enabled / reachable / usage` 正常。

| 现象 | 最可能的原因 | 处理 |
| --- | --- | --- |
| 8090 打不开 | Docker Desktop 没起 / 容器没起 | 先起 Docker Desktop，再跑 `v2.0/ai/start-dify.ps1` |
| `/api/ai/health` 里 `reachable=false` | Dify 容器没起（直连通道仍可用） | 起 Dify；或不管它，演示照样走直连 |
| 后端起不来、报端口占用 | 容器占了 8080，或上一次进程没退干净 | `docker compose -f docker-compose.app.yml down`；`netstat -ano | findstr 8080` 后结束进程 |

## 5 容器化交付

```bash
cd v2.0
docker compose -f docker-compose.app.yml build
docker compose -f docker-compose.app.yml up -d
docker compose -f docker-compose.app.yml ps      # 期望 app / web 两个都 healthy
```

- 端口：后端容器 `8080`、前端 nginx `8081`（`/api` 反代到 `app:8080`）。
- 资源与日志：`mem_limit 1g / 256m`，日志轮转 `50m×3 / 20m×2`，两个服务都有健康检查。
- 上传资料落命名卷 `arw-app-file-store`（容器重建不丢），网络 `arw-app-net`。
- 宿主机 MySQL(3306) 与 Dify(8090) 通过 `host.docker.internal` 访问；密钥用环境变量注入（`AI_LLM_KEY`、`AI_REPORT_APP_KEY`）。
- 合规对照与整改记录见 `word/学情预警系统_Docker部署合规差异记录.docx`。

## 6 备份与恢复

```bash
# 数据库（结构 + 数据 + ngram 全文索引会随建表语句恢复）
mysqldump -uroot -p --default-character-set=utf8mb4 study_warning_system_v2 > backup_$(date +%F).sql

# 上传资料（课件本体）
# Windows 直接复制目录：v2.0/backend/file-store
```

恢复顺序：建空库 → 导入 dump → 把 `file-store` 放回原路径（`app.file.store-dir`）→ 起后端 → 教师端点一次知识库同步
（`POST /api/teacher/ai/kb/sync?courseId=1`）把课件重新入库。Dify 自身的备份/升级见 `v2.0/ai/README.md` §7。

## 7 常见故障

| 现象 | 最可能的原因 | 怎么处理 |
| --- | --- | --- |
| 5173 白屏 / 404 | 前端没起或起了别的端口 | 看终端输出端口；`npm run dev` 重起 |
| 页面能开但接口 401 | 令牌过期（12 小时） | 退出重新登录 |
| 接口 502 / 代理错误 | 后端没起或不在 8080 | 确认 8080 在听；vite 代理指向 `127.0.0.1:8080` |
| 报告/解释卡一直是「规则生成」 | 模型通道不可用或 Key 未配 | 看 `/api/ai/health`；配 `AI_LLM_*` 或起 Dify |
| 答疑说"资料里没有" | 该课程知识库没入库 / 问题确实不在资料里 | 教师端「课程内容 → 资料库」上传课件（上传即入库） |
| AI 出题报"模型通道未配置" | 同上 | 配 `AI_LLM_KEY` 后重启后端 |
| 看板指标全是 0 | 没跑过判定 / 干预数据没补 | 跑一次判定；执行 `sql/29_seed_intervention_demo.sql` |
| 上传文件后下载 404 | `file-store` 卷/目录丢了 | 检查 `app.file.store-dir` 与卷挂载 |
