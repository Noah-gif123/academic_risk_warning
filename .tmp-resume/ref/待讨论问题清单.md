## 一、仍未定：6 条

**Q1 · 风险趋势图还留不留** 🟠
- 起因：你定了"每日快照删了"。趋势线的数据点原本就来自每日快照，删掉后趋势图**没有数据来源**。
- 选项 A（推荐）：快照改为**评估时 / 数据变更时写一条** —— 一学期约 5~10 个点，趋势图仍可用，库里也不再堆垃圾数据。
- 选项 B：趋势功能整体删除（只显示"当前状态"，不显示变化曲线）。
- 待你定：A 还是 B。

**Q2 · 1/3 挂科门槛的分母用哪一个** 🔴
- 背景：你定了"期末由任课老师申报本课真实上了几周几次，教务确认"。
- 选项 A（推荐）：门槛分母用**教务确认后的实际课次**（更贴合学校真实规则；期末才判定，来得及）。
- 选项 B：门槛分母固定用**计划课次**，"申报的实际课次"只用于覆盖率体检。
- 待你定：A 还是 B（选 A 时，申报值会改变所有学生的挂科判定，必须留痕并记录进快照）。

**Q3 · AI 停用的具体做法** 🟠
- 你的意见：先注释。我的建议：不写大段注释，用**可回滚的停用**。
- 选项 A（推荐）：AI 相关类统一加 `@ConditionalOnProperty(name="agent.enabled", havingValue="true")`，配置置 false 即全部不生效；恢复只改一行配置。
- 选项 B：先打 tag `v1.3.0-ai-complete`，然后**直接删** AI 代码与前端面板；要恢复就 checkout 回来。
- 待你定：A 还是 B（两者都不会留下"注释坟场"）。

**Q4 · 导员端"只展示中高风险"的边界** 🟠
- 你的意见：导员只看中高风险学生，低风险不看。
- 需明确："中高"是指**风险分 ≥40（黄/橙/红）**，还是只给**橙及以上（≥60）**？
- 我的建议：导员名单按 **≥40** 过滤（黄进名单但只带"需关注"标签；橙/红才进重点关注与升级链）；绿色完全不出现在导员视图。

**Q5 · "期末需多考分数"要不要给学生看** 🟡
- 背景：通道 A 现在用"需多考 > 100 → 实际不可达"，这个数很直观（如"期末要考 130 分（满分 100）"）。
- 风险：可能诱导学生"算着缺课"。
- 我的建议：**教师端/教务端显示具体数字；学生端只显示状态**（"已缺 5 次 / 还能缺 −1 次 → 已触发直接挂科"），不给"需多考 X 分"。

**Q6 · 基础表清单是否需要增删** 🟠
- 你让我提议"还有哪些基础信息可以留"。我提议的基础层 10 张：
  `term`（学期）、`sys_account`（账号）、`student`、`teacher`、`counselor`（导员）、`admin`、`major`（专业/学院）、`administrative_class`（行政班）、`course`（科目）、`course_knowledge_point`（知识点）
- 可选再加：`teacher_title`（职称/是否新教师，与 Δ 收缩有关）、`student_status`（在读/休学/退学——影响是否参与预警）。
- 待你定：这 10~12 张是否够；还有哪些"基础信息"你认为该留。

## 三、已关闭（不再讨论）

| 项 | 结论 |
|---|---|
| 1/3 挂科线 | `N_max = floor(总课次/3)`；12 课次 → 缺 3/4 次只扣分、缺 5 次挂科；剩余可缺 = 0 显示"再缺一次即挂" |
| 通道 A 第三条判据 | **期末满分 100 硬上限**：`(60−W+P)/r_f > 100 → 实际不可达`（原"历史期末最高分"已废弃——大一无历史、跨课程也不可比） |
| 通道 A 可用时点 | 措辞改为"第 2 周起**可算**"；首响通常在学期中段，早期预警由行为信号（通道 B）承担 |
| 扣分公式 | `P = 2×缺课 + 1×迟到 + 1×max(0, 请假−3)`，无上限、不截断，`T` 可为负 |
| 请假免扣 | **每学期每门课 3 次** |
| 迟到/缺课现实口径 | 老师会把"点名发现缺课"放宽为迟到 ⇒ 缺课次数是严格下界，通道 A **只漏报不误报** |
| 总课次 | 计划课次（教务开学导入）+ 实际课次（老师期末申报、教务确认） |
| 覆盖率 | `<1/2` 提醒 + 置信度判低；期内只对"连续 4 周零录入"软提醒，正式考核在期中/期末归档节点 |
| 学生历史挂科 | **新建表**（跨学期）；大一上无数据、最早大一下才有；模型需支持"无历史" |
| 学生端考勤 | **只读，无申诉功能** |
| 缓考 | **照常预警**（预警发生在期末考前）；缓考只影响最终成绩结算 |
| 重修班 | **不作特殊统计处理**：单独开班 + 课程级按人数加权，高挂科率是事实 |
| 退课 | 课程列表显示「经教务批准已退课」并移除；相关预警/快照作废 |
| 成绩构成 | 开学第一周上课前由课程组统一确定（无额外工作量）+ 学期内锁死不可改 |
| 课程组裁决 | 不存在"未达成一致"场景（开学前就定） |
| 归档后修改 | 不能改，需教务操作且留痕 |
| 期中归档审核 | 教务**不逐门审核**，只做覆盖率体检 + 随机抽查 |
| 回执 | 班集体提醒与个体提醒**都要** |
| 导员端粒度 | 只展示中高风险（边界见 Q4） |
| 多科目预警 | 3 门及以上 |
| 无效判定 | 下次快照即可判 / 最长 2 周 / 期末终判 |
| 问卷链路 | 结构固定为"导员→教务→授课组"，不再改动 |
| engine_version | 规则·权重·公式任一变化即升版 |
| 每日全量快照 | **删除**（趋势存废见 Q1） |
| 旧代码复用 | 不复用：旧口径单测删除，前端页面按新模型重写 |
| 数据库范围 | 只留基础表；业务数据全部新建；先理清表清单与顺序，再找数据 |
| AI 功能 | 先停用（含 agent 与知识库），方式见 Q3 |
| 教师端风险概览 | 关 AI 时必须仍返回数据（AI 解读单独 try/catch）—— 已列为必修 bug |
